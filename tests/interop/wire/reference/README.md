# Reference Packet Captures

Canonical wire captures of IEC 61850 protocol exchanges between
libiec61850 client and server programs. These are black-box captures
of compiled binaries — no source code was read or copied.

Use these to verify encoding correctness during development:

```sh
tshark -r mms_canonical.pcap -d 'tcp.port==10400,tpkt' -Y mms -V -O mms
tshark -r goose_sv.pcap -Y 'goose or sv' -V
```

## Captures

| File | Protocol | Contents |
|------|----------|----------|
| `mms_canonical.pcap` | MMS/TCP | Identify, GetNameList (domains + variables), Read — minimal reference |
| `mms_services.pcap` | MMS/TCP | All mms_utility operations + client_example1 read/write cycle |
| `mms_control.pcap` | MMS/TCP | Control server: Read, Write, GetVariableAccessAttributes patterns |
| `goose_sv.pcap` | GOOSE + SV | GOOSE publisher (1 frame) + SV publisher (40 frames) on veth |
| `mms_report.pcap` | MMS/TCP | Ed.2 reporting (WP-2d self-conformance, regenerated post-WP-2z from the conformant report-encoder scenario): RCB discovery, component reads/writes (Resv/RptEna/DatSet/OptFlds/TrgOps/GI/EntryID/PurgeBuf), Ed.2 enable-without-reserve rejection, 7 InformationReports (URCB dchg + GI, BRCB live/resume/post-resume), client loss + EntryID resume after reconnect — report bodies dissect as IEC 61850 reports (rptID/seqNum fields visible to tshark); validate_pcap.py mms_report passes 6/0 |
| `mms_control_ed2.pcap` | MMS/TCP | Ed.2 control (WP-2d self-conformance, regenerated WP-C1 from the WP-2w conformant scenario): status + ctlModel Reads, Select as a Read of `$SBO` (answered with the object reference string), Operate as a Write of the 8-1 originator structure to `$Oper`, CommandTermination as an unsolicited InformationReport on `$Oper`, Select + `$Cancel` Write, operate-without-select on a strict object rejected in-band as a Write-Response DataAccessError — every PDU dissects with zero BER errors |
| `rgoose_rsv.pcap` | R-GOOSE + R-SV/UDP | 90-5 routable profiles (WP-4e, self-conformance): 5 plain R-GOOSE SPDUs (dport 10201), 5 plain R-SV (10202), 3 HMAC-SHA256-signed R-GOOSE frames (10203) and 3 signed R-SV (10204) on loopback, generated by this repository's own `rgoose_wire_pub` scenario |

## How captured

- MMS: `server_example_basic_io` / `server_example_control` on port 10400,
  queried by `mms_utility` and `client_example_control`
- GOOSE/SV: `goose_publisher_example` / `sv_publisher_example` on veth pair
- All on loopback/veth, captured with tshark
- libiec61850 version: 1.6.x
- `mms_report.pcap` / `mms_control_ed2.pcap`: this repository's own
  server + client (tests/interop/wire/mms_report_wire.c,
  mms_control_wire.c) on TCP loopback ports 10610/10611, captured with
  tcpdump on lo (Ed.2 wire conformance — our bytes dissected by the
  neutral tshark MMS dissector). `mms_report.pcap` was regenerated
  after WP-2z (the original capture predated the conformant report
  encoder by hours — its InformationReports used the house layout
  and failed validate_pcap.py); `mms_control_ed2.pcap` was
  regenerated in WP-C1 from the current (WP-2w) scenario with the
  rootless user+network-namespace tcpdump fallback — the previous
  capture predated WP-2w and documented the house-encoded flow
  (malformed Select/Operate PDUs, ConfirmedError rejection); both
  are reference material only, no test consumes them
- `rgoose_rsv.pcap`: this repository's own 90-5 publisher scenario
  (tests/interop/wire/rgoose_wire_pub.c) on UDP loopback ports
  10201-10204, captured with tcpdump on lo inside a rootless
  user+network namespace (WP-4e wire conformance — tshark has no
  90-5 dissector, so the SPDU session header is asserted as raw
  byte patterns at the offsets documented in src/asn1/rgoose_ber.c)

```sh
tshark -r mms_report.pcap -d 'tcp.port==10610,tpkt' -Y mms
tshark -r mms_control_ed2.pcap -d 'tcp.port==10611,tpkt' -Y mms
tshark -r rgoose_rsv.pcap -Y 'udp.port==10201 || udp.port==10203' -V
```
